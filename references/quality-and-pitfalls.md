# 验收方法与常见问题

这份清单来自《异县1992》的动作制作与接入。里面的像素数、帧数和幅度是该项目的例子，不是所有人物通用的硬阈值。先按当前项目的人物尺寸、镜头和动作目的设定标准。

## 1. 先看动作是否成立

先看逐帧表，再看正常速度循环，最后看目标游戏尺寸。放大图能看到手指和边缘，游戏尺寸才能看出玩家是否读得懂动作。

| 动作 | 应当能读到 | 需要返工的信号 |
| --- | --- | --- |
| 待机、呼吸 | 姿势稳定，胸肩有小幅起伏 | 整个人上下平移；头、箱子一呼一吸地变大 |
| 行走 | 左右腿交替承重，有摆动腿经过身体下方的过渡 | 一条腿一直钉住；反复高抬同一条腿；后半轮重复前半轮 |
| 跑步 | 交替支撑，摆臂，符合设计的腾空阶段 | 只是把走路播放加快，却声称新绘了跑步 |
| 徒手攻击 | 准备、向目标伸拳、接触、收拳，防守手保持合理 | 手臂甩向身后；连摆几次却没有清楚打到前方 |
| 挥棒、短刀、菜刀 | 武器路径、握点和重量转移连贯 | 断棒、双武器、武器穿手，命中姿势朝错方向 |
| 搬运 | 双手与负重姿势合理，腿部可以承重 | 三条胳膊、旧手残影、双裤腰，腰部接缝一走就裂 |
| 举起、放下、投掷 | 手接触物品的时机、运动路径和释放点一致 | 物品吸到头顶；从脚下弹出；脱手后又回到手中 |
| 倒地、起身 | 动作始终有明确支撑与重心 | 起身时突然换身高；倒地人物被缩放成站立高度 |

一个动作有很多时间采样槽，不代表有同样多的新绘姿势。审查时分别记录原始姿势数、播放帧数、重复停留和插值帧。

## 2. 定位问题和动作问题分开修

### 共同画布、站立比例、联合裁切

1. 固定该角色的站立身高参考。蹲下、坐下、倒地后的可见高度可以改变。
2. 把同一动作的姿势放在共同坐标系中，用共同人体尺度处理整组。
3. 校准位置后，对整组求一次联合包围盒，统一裁切并保留武器、鞋尖和手的安全边距。
4. 输出每帧相同的单元尺寸，以及变换后的共同锚点。不要把每帧的紧包围盒各自拉满格子。

逐帧按可见高度归一，会把下蹲人物的头放大；把球棒、举起的箱子计入身高，会使没有这些伸展的姿势突然变大。

### 锚点要跟着动作语义选

- 原地挥击可以用可信的身体核心横坐标和共同地面线，去掉生图单元里的站位噪声。
- 有意前冲的攻击、蹲下、跳跃、倒地不能机械锁死全身所有方向。保留设计的运动，只修参考坐标漂移。
- 行走的腾空脚不代表地面移动。按支撑阶段标定地面，保留人体起伏；不要逐帧把最低像素强拉回同一条线。
- 搬运身体锚点与手掌握点分别标定，箱子或武器不参加人体核心定位。

《异县1992》攻击 V2 曾把身体核心横向平均跳变从约12.5源像素降到0.3像素。这个量级说明了定位修正的作用，不保证另一套画也应达到同样数字。任何指标变好之后，都要重新看动画。

### 自动测量也会被道具骗过

腐蚀 alpha 可以暂时去掉细长武器，但不是可靠的通用人体分割器。武器过顶、手臂贴头和厚木棒都可能残留，污染质心或头围。

检查测量用的蒙版和选中区域：身体核心不应随着棒尖伸到画面远处；头围不应把抬起的双臂算进去。必要时用人工标注、可靠的胸部区域或人工确认的参考点。《异县1992》的蓝色衣服区域可以用于它自己的胸部定位，不能直接套到别的配色。

## 3. 尺度修正保持克制

区分三类现象：

- **整体缩放漂移**：头和人体稳定参考一起变大或变小。
- **真实姿势改变**：膝盖弯曲使身高下降，但头部尺度基本保持。
- **测量污染**：手、武器或头发轮廓让某几帧的代理指标失真。

不要直接按每帧原始头围反向缩放。先排除污染帧，再决定是否值得修。《异县1992》攻击 V3 对可信头宽和头高的几何平均做低阶循环谐波拟合，并把整体修正限制在约±3%；更激进的修正虽然压平头围，却加剧身高抖动。

循环拟合只适合循环序列。单次攻击、倒地和死亡不可为了首尾数学闭合而扭曲真实结束姿势。没有可信测量或足够有效帧时，保留已审源帧，或重做错误的关键姿势。

## 4. 透明边缘与颜色

PNG 或无损透明 WebP 是素材与边缘检查的依据。GIF 便于 GitHub 预览，但只有全透明或不透明，无法保留柔和 alpha。

- 有干净的真实透明源图就沿用 alpha，不必先铺品红底再抠一遍。
- 使用键色时先检查角色本身是否有相近颜色；避免把衣服、鞋和头发误抠。
- 抠像应去除底色污染，并在白、深色、棋盘格底上看边缘。硬阈值直接清零可能留下锯齿和品红描边。
- 连通域提取要确认武器、手指和独立小部件是否被保留。机械地只保留最大连通域，可能删掉故意分离的武器特效。
- 几何变换用预乘 alpha 安全重采样；颜色归一化与最终乘255只能各做正确的一次。
- 同时检查不透明像素的 RGB、饱和度和 alpha。只看 alpha 会漏掉“人物全白但轮廓完全正确”的错误。

推荐给重采样保留一个恒等检查：缩放1倍应近乎不改变图像；然后对照变换前后的不透明颜色统计和实际画面。不能用一个统一的颜色阈值替代目视检查。

## 5. 循环与播放节奏

1. 先确认这是循环动作，还是单次完成后保持末帧的动作。
2. 循环动作看最后一帧到第一帧的衔接，不只看中间各帧。
3. 最后一帧如果只是第一帧的完整重复，可去掉重复的端点；如果它承担有用过渡，不要按“循环必须删末帧”机械删除。
4. 单次投掷、死亡或开门不能靠正放再倒放，伪装成新的连续动作。
5. 为阅读方便循环播放的评审 GIF，应明确是试看片。运行时的单次播放语义仍写进动作元数据。
6. 攻击应有准备、接触、收招的节奏。挥击段可以短，命中姿态必须仍可辨认。

GIF 时长按百分之一秒表示，不能任意精确到1ms。帧合并也可能使编码后的帧数少于源PNG数；验收应检查解码画面与总时长，不把编码帧数等同于独立原画数。

## 6. 搬运的最新经验：优先整个人物姿势

早期举箱试看片曾用新上身加既有行走腿分层。它能稳定脸和箱子，但接入游戏后出现腰部与裤子不协调，最终改回每方向四张完整原身体姿势。不要把旧试验的混拼方式写成默认做法。

分层适合来源协调的部件或小幅呼吸，不适合直接把不同体型、视角、裤腰、光照的上下身接起来。确需分层时，逐帧检查腰线、颜色、阴影、遮挡和手臂残留；修不好就换完整姿势。

搬运物品在游戏中应是独立层：

- 每帧保存真实手心握点，身体帧与握点使用同一个帧索引。
- 同步完成裁切、缩放、镜像后，握点也要执行相同坐标变换。
- 举起、持物、走路、投掷之间检查连续性；脱手发生在当前手部位置，不能从脚下或常量“头顶点”发射。
- 单独测试八个方向、玩家和队友、角色切换、暂停、物品碰撞与掉落。

物理高度、遮挡顺序和显示比例都参与最终观感。只看脱离游戏的 GIF，不能证明游戏里的搬运正确。

## 7. 补帧与复用的边界

RIFE 等补帧器可以让时间采样更密，不能保证发明正确的人体结构。快速旋转的细长武器容易断裂、分叉和双影；失败的补帧应丢弃，而不是为了帧数把它塞进成品。

保留每组动作的制作类型：新绘、既有帧复用、校准、局部分层、镜像、反序、补帧。左右镜像须检查服饰、单侧挎包、持械手和光照是否允许；镜像不等于独立新绘。放下复用举起反序、关门复用开门反序，只有动作逻辑成立时才用，并明确标记。

## 8. 最小交付验收表

- 源图和版本保留，能说明哪些帧来自哪里、做过哪些变换。
- 每帧RGBA、共同尺寸、共同锚点、动作站立参考高与实际总时长可读取。
- 接触帧、循环/单次语义和方向明确；没有把重复停留算作新姿势。
- 放大逐帧表、正常速度预览和目标尺寸预览都看过。
- 角色身份和比例稳定，动作方向正确，无断肢、多手、残影或意外裁切。
- 白底、深底和透明素材检查通过；颜色没有变白或染上键色。
- 如需接入游戏，实际加载图集验证动作选择、帧顺序、接触时机、锚点、换装和物品握点。
- 修复某一动作后，比对其他动作的文件哈希，避免重打包时覆盖已认可成果。

“检查通过”只覆盖实际做过的检查。预览通过、图集打包通过、引擎运行通过是三个不同阶段，应在交付说明中分别写清。
