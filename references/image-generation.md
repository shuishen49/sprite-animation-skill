# 生图方法

本 Skill 的流程里，**生图只负责角色与姿势**，其余（抠像、对齐、裁切、排时、打包）由确定性脚本完成。
本仓库不自带图像模型、视频服务或 API 凭据；具体调用哪个生图工具，取决于当前环境实际可用的能力。
开工前先确认工具真的能调用，**不要因为文档里写过就声称已接通**。

顺序一般是：先做对一个动作的一个方向，再按授权范围扩展。提示词模板见 [prompts.md](prompts.md)。

## 灵感平台（linggan）Go 直连

用户级 skill `linggan-go-image`（装在 `~/.workbuddy/skills/linggan-go-image/`，跨项目可用）。
用平台 API Key 换短期授权，直连 Go 后端生图并下载结果。

**凭证已就位**：`~/.workbuddy/.linggan_api_key`，脚本自动读取，不需要手动 export。
**不要把 Key 写进本仓库、脚本源码或任何生成结果里。**

### 快速使用

**推荐 v2**（长提示词稳、自动重试、每轮换新凭证）：

```bash
python "<技能目录>/scripts/linggan_image_v2.py" \
  --prompt-file "提示词.txt" --out "<输出目录>" --tries 6
```

**v1** 只支持 `--prompt` 内联，长提示词容易撞「回复超过缓冲上限」；
但**只有 v1 支持 `--reference` 传参考图改图**，做「以参考图约束角色身份」时用它：

```bash
python "<技能目录>/scripts/linggan_image.py" \
  --prompt "你的作图描述，请直接生成图片" --out "<输出目录>" --reference "角色参考.png"
```

脚本会自动完成授权 → SSE 生图 → 下载，并打印保存路径。

### 头号坑：「回复超过缓冲上限」

报错形如 `Go 返回错误: "回复超过缓冲上限"`。**与余额、额度、Key 都无关**——
授权返回 `code:200` 且拿到 chat_token 就说明凭证正常。真实原因是**上游回包太大**：
图片以 base64 内联在 SSE 正文里回传，画面越复杂 PNG 越大越容易超限。

降体积三招（按效果排序）：

1. 提示词里写死「**纯白背景，只有细黑线轮廓，不要明暗排线、不要灰度阴影、不要上色、不要纹理，大量留白，工程制图风格**」——白底极简线稿的 PNG 能小一个量级。
2. **拆任务**：别让一张图塞太多内容（如九宫格分镜），宁可多跑几次、自己用 PIL 拼。
3. 缩短提示词本身，模型少复述、少生成解释文字。

**`image_generation` 必须为 `true`**。设成 `false` 会走纯文本通路，只回一段文字、根本不出图。

失败**不扣币**（只返回文字扣 1 个星火币，出图扣 7 个），可以放心重试——`--tries` 就是干这个的。

### 关键约束

- **每次请求必须用全新凭证**：重新走授权拿新的 `request_id` + `chat_token`，不要复用；也不要携带 `conversation_id` / `conversation_proof`。一次失败就作废这一轮，换新凭证重试。
- 尺寸、比例、风格、透明背景等要求**写进提示词正文**，不要用 `size`、`image`、`timeout_sec` 字段。
- 参考图：完整标准 Base64（**不带** `data:image/...;base64,` 前缀）放进 user 消息的 `files`，最多 8 个，原始文件合计 ≤ 2.8 MiB。
- SSE 中遇到 `error` 立即报错；仅网络 EOF 不算完成。
- `sandbox:` 链接不是公网下载地址；没拿到实际图片就如实报告「未返回图片」。
- 出错或超时后**不要自动重放付费请求**；调用前确认用户愿意付费。

### 拼表脚本：绕开「九宫格角色必跑偏」

让模型一次出九宫格，角色长相经常崩（硬约束造型尤其明显，比如「方盒头机器人」会被画成斜切棱柱）。
**正确做法是把已验证准确的素材拼起来**——三视图、单独出好的格子，裁成统一比例再拼：

```bash
python "<技能目录>/scripts/make_contact_sheet.py" \
  --out "分镜表.png" --cols 3 --cw 1280 --ch 720 \
  --title "动作分镜表" --preview 1300 \
  --cell "tiles/01.png|① 特写" --cell "tiles/02.png|② 中景"
```

`--crop "center,top"` 控制裁切锚点，主体被切到头/脚时改这里。

这条和本 Skill 的路线 A 是一致的：**小排图能帮模型共享角色外形，但格线不是可靠裁切边界**，
棒尖可能越格、手脚可能是独立连通部件——所以宁可分开出图再拼。

### 环境注意

- **不要用 PowerShell 版脚本**，沙箱里起不来；统一走 Python 脚本。
- 需要 Pillow 做后处理（裁切/拼图）时先 `python -m pip install pillow`。

## 换成别的上游工具时，等价要求是什么

不管用哪个生图/改图服务，对序列帧来说这几条必须满足，否则后面全部白做：

1. **能带参考图**约束角色身份（发型、脸、头身比、服装配色、鞋、单侧饰物、持械手）。
2. **能固定相机、朝向、灯光和画布规范**，多帧之间保持一致。
3. **能明确指定姿势内容**，而不是只给一句「做一个走路」。
4. **输出留白足够**：为武器、跨步、腾空和挥动幅度留出边距，避免越界被裁。
5. **背景可分离**：要么直接给透明/纯色底，要么提供保留柔和 alpha、能去溢色的抠像能力。

## 生图之后必须做的检查

模型可能**少画、多画或重复画**。生成后先数实际姿势数，再逐姿看：漏格、重复姿势、改脸、画错武器。
不合格的关键姿势**有针对性地重画**（带回原参考和相邻姿势，明确要改的肢体路径与必须保留的设计），
不要靠后期缩放、裁切或补帧去掩盖。

不要用整张人物旋转或只挪同一条胳膊，冒充已重画一组全身动作。
