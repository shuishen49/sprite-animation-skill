# 从参考图到连续序列帧

## 1. 建立角色与动作规格

打开参考图，记录发型、脸、头身比例、服装配色、鞋、单侧饰物、持械手及画风。把站姿作为尺寸参考，另存动作规格；例如“身体参考600px，游戏显示38px”，后续所有动作以同一个比例显示。蹲下、坐姿、倒地的可见高度自然会更小。

确认要制作哪些动作和方向：`down/left/right/up` 与四个斜向分别列出。侧向镜像需要检查挎包、文字、武器握手和光照；正面与背面不能用左右镜像代替。来源标签可用 `new-key-poses`、`reused`、`aligned`、`layered`、`mirrored`、`reversed`、`interpolated`。

规格至少保存阶段、独立姿势数、时长、循环语义、命中/接触帧和交付范围。用户只看试片时先交付试片；已经要求全套时，按规格继续完成。别把“预览可播”记成“游戏已接入”。

## 2. 规划姿势，而不只要求模型“连续”

侧视走路的示例完整周期：

1. 左脚在前接触，右脚在后。
2. 左腿承重，身体略下降，右脚离地。
3. 右腿从身体下方经过，左腿支撑。
4. 右腿前摆准备接触。
5. 右脚在前接触，左脚在后。
6. 右腿承重，左脚离地。
7. 左腿从身体下方经过。
8. 左腿前摆，接回下一轮第1姿。

这是设计参考，不保证生图模型一次做到。若后半轮只是重复前半轮，即使图像有细微差别，也没有形成正确左右脚周期。

直拳示例：护拳 → 胸前紧凑准备 → 向前半伸 → 命中 → 原路收拳 → 护拳。清楚指定一轮只打一拳，另一手留在防守位置。挥棒要让握点沿合理弧线移动，接触阶段朝目标方向，不能读成向前推棍。

## 3. 生成和修正源姿势

### 生图路线

先调用实际可用的图像生成/编辑工具，以参考图约束身份。固定相机和朝向，留出武器、双手与跨步所需空间。生成后检查实际姿势数量，模型可能少画、多画或重复画。

小排图可以帮助共享角色外形，但格线不是可靠裁切边界。棒尖可能越格，透明源图的手脚也可能是独立连通部件。先看整图，再分离姿势；给输出放入相同尺寸的透明画布。需要修正某一姿时，带回原参考和相邻姿势，明确要改的肢体路径与必须保留的设计。

不要用整张人物旋转或只挪动同一条胳膊，冒充已重画一组全身动作。局部变形可以用于呼吸、衣料等，按实际做法标注。

### 视频路线，能力可用时再采用

为首帧留足画布边距，按实际服务的输入要求设置尺寸。提示固定相机、角色居中、原地走、无缩放、无地面投影、可分离背景。抽取足够完整的运动，而不只截“看起来最像走路”的几帧。

寻找同一只脚两次相同接触之间的周期；步态信号自相关可能首先得到半周期，需要目视确认左右腿身份。对时域 `[t0,t0+周期)` 取样，排除重复终点。记录视频源、选帧索引和输出时长。

视频中若缺少完整周期、肢体变形或角色离开画面，重新生成比强行插值更合适。模型、服务名不明时如实记录未知。

### 绑定模型路线

检查模型是否有骨架、蒙皮和可用动作。需要时重定向或制作动画，选定渲染相机、身体世界高度、灯光和透明背景，渲染完整周期。跳跃或前冲等动作保留 root motion 或单独导出，不在截图后误消除。

## 4. 去背景、提取、对齐

透明输出合格时直接使用。键色图应检查实际背景颜色和角色配色，使用保留柔和边缘、可去溢色的工具。本仓库不自带抠像器，也不自动安装或调用它；选哪个工具前，先确认它满足这几条：

- **能自动识别或指定键色**，而不是要求手填一个猜出来的颜色；先采样实际背景色再抠。
- **保留柔和 alpha**，不是二值硬阈值。硬阈值直接清零会留下锯齿和键色描边。
- **能去边缘溢色**（decontam），把键色从半透明边缘像素里还原成角色本身的颜色。
- **有白底/深底检查**，能报出残余键色，便于复核。

历史实验里这类工具的命令形如 `cutout <源图> --out <输出> --key auto --decontam auto --white-check`；
具体工具的参数名不同，执行前先看已安装版本的 `--help`。

按可信的身体参考确定一次尺度，再修画布中的位置噪声。自动检测武器、头部或胸部的蒙版都要可视化检查。行走保留承重起伏，攻击保留下蹲，跳跃保留离地高度。

需要对齐时保存源画布锚点。可用身体核心X与地面Y作为原地动作的定位点；这是约定的参考位置，不必是单一可见像素。手持物另存每帧手心点，不能把它和身体定位点混为一谈。

在统一坐标里对整组取联合包围盒，统一裁切。不要逐帧紧裁再分别拉满格子。保持源图备份，记录所有变换。

## 5. 排时与打包

选择循环或单次，明确末帧是否停留。攻击的蓄力和收势可以慢，挥出阶段可以快，但命中姿势必须可读。预览慢放和运行时攻击窗口可以不同，要分别标明。

先看最后到第一帧的接缝；确认重复端点后才去掉末帧。相似度可以辅助判断，不能发现“同一张画其实承担接触停留”这样的动作意图。

准备好同尺寸透明 PNG 后，使用 [打包脚本](packing.md)。它不负责生图、抠像、修步态或估计身体尺度。输出 `report.json` 只列事实，不能代替动作审核。

## 6. 看三种尺度，再判断完成

逐帧表检查肢体、武器、手和边缘；正常速度检查节奏与循环；目标游戏尺寸检查动作是否读得清。至少在浅色和深色背景复核透明边缘。

如果接入游戏，按元数据的身体参考高和共同锚点绘制；攻击命中姿势对齐真实伤害窗口，举起/持物/投出共用当前帧手心点。检查所有声明支持的方向以及玩家、队友、控制切换。不要只拿离线GIF作为运行时证据。

保留通过的旧动作，只替换需要修复的组。最后交付具体路径、来源、姿势数、时长、方向覆盖、已检查内容和剩余缺陷。
